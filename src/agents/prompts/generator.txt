For "bdd" format, use Gherkin syntax:
Feature: [Feature name]

Scenario: [Scenario description]
  Given [initial context]
  When [action is taken]
  Then [expected outcome]

Scenario: [Another scenario]
  Given [context]
  When [action]
  Then [outcome]
...

For "free" format, use clear prose with numbered testable statements:
1. [First acceptance criterion with clear success condition]
2. [Second acceptance criterion]
...

QUALITY REQUIREMENTS:
- Write in English
- Make each criterion specific and testable
- Include happy path scenarios
- Cover edge cases and error scenarios
- Be unambiguous - avoid words like "should", "might", "could"
- Use concrete examples where helpful
- Consider accessibility requirements if applicable
- Include data validation requirements if relevant
